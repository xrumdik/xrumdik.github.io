## О проекте

Когда серверов становится больше десятка, обновлять их вручную долго, а главное, нет уверенности, что на каждом сделано одно и то же. Полностью автоматические обновления подходят не всегда: на важных серверах хочется сначала увидеть, что именно будет установлено, и самому решить, когда перезагружать.

Задача состояла в том, чтобы обновлять серверы Linux и Windows одним способом: с предварительным просмотром, понятным отчётом и перезагрузкой только там, где она нужна. Для этого выбран Ansible.

## Основные возможности Ansible

**Открытый исходный код:** Ansible бесплатный, распространяется по лицензии GPL, устанавливается из пакетов обычного дистрибутива и не требует лицензий и подписок.

**Без агентов:** на управляемые серверы ничего ставить не нужно. К Linux Ansible подключается по SSH, к Windows по WinRM.

**Сценарии простым текстом:** действия описываются в файлах (плейбуках) на понятном языке, которые читаются как инструкция и хранятся в Git. Одним сценарием можно обработать десятки серверов.

**Группы серверов:** серверы собираются в группы (Debian, RHEL, Windows, контроллеры домена). Можно запустить сценарий на группе, на одном сервере или на группе за исключением нескольких серверов, предварительно посмотрев, кого он затронет.

**Хранилище паролей:** встроенный Ansible Vault шифрует пароли, поэтому в открытом виде они нигде не лежат.

**Повторяемость:** сценарий можно запускать снова и снова, и результат будет одинаковым. Ничего лишнего он не делает.

## Пример 1: обновление Linux

Для Linux используются три отдельных сценария, которые запускаются по очереди:

1. **Проверка.** Ничего не устанавливает, а только показывает, какие пакеты будут обновлены, и считает их по серверам. Для каждого пакета видна старая и новая версия.
2. **Установка.** Перед обновлением и после него запоминается список пакетов, поэтому в отчёте видно, что обновлено, что установлено заново и что удалено. Сервер при этом не перезагружается, а только сообщает, нужна ли перезагрузка и по какой причине (например, обновилось ядро).
3. **Перезагрузка.** Перезагружаются только те серверы, которым это нужно, и по одному. Перед каждым запрашивается подтверждение. Если сервер не поднялся, остальные не трогаются. После загрузки можно проверить, что нужные службы запущены, и увидеть версию ядра до и после.

Подключение устроено безопасно: Ansible входит по SSH-ключу под обычной учётной записью без прав администратора, а права администратора получает через `su`. Пароли хранятся в Vault.

## Пример 2: обновление Windows Server

Для Windows работает такая же схема из трёх сценариев: проверка, установка, перезагрузка.

- **Проверка** находит критические обновления, обновления безопасности и накопительные пакеты. Если в сети есть WSUS, обновления берутся с него.
- **Установка** выдаёт список установленных обновлений и ошибок. Перезагрузка при этом не выполняется, а нужна ли она, определяется по признакам в самой системе.
- **Перезагрузка** проходит так же, как на Linux: только где требуется, по одному серверу, с подтверждением и проверкой служб после запуска.

Ansible подключается к Windows через служебную доменную учётную запись. Контроллеры домена обрабатываются отдельно: их администраторский пароль нигде не хранится и вводится вручную при запуске.

## Что улучшилось

**Предсказуемость:** перед установкой видно, что именно обновится, а после неё есть отчёт по каждому серверу.

**Единый способ для разных систем:** Linux и Windows обновляются по одной схеме, с одинаковыми шагами и отчётами.

**Контролируемая перезагрузка:** она выполняется только там, где нужна, по одному серверу и с подтверждением, поэтому сбой одного сервера не приводит к остановке всего остального.

**Безопасность:** пароли хранятся в зашифрованном виде, на серверах не нужен вход под root по SSH, а пароль администратора контроллера домена вообще не сохраняется.

**Меньше рутины:** вместо обхода серверов по одному одна команда на группу. Сценарии лежат в Git, поэтому изменения видны и их можно откатить.

## Итог

**Что стало сложнее:** нужна отдельная управляющая машина, и её защита критична: тот, кто получит к ней доступ, получит доступ ко всем серверам, поэтому доступ ограничивается, а мастер-пароль хранится ещё и вне этой машины. Сценарии нужно сопровождать, а для Windows заранее настраивать WinRM и права служебной учётной записи.

**Результат:** серверы Linux и Windows обновляются по понятной схеме на бесплатном открытом решении: сначала просмотр, потом установка, затем перезагрузка только там, где она действительно требуется.
