## О проекте

В большинстве доменов у локального администратора на всех компьютерах один и тот же пароль: его задали в образе системы, и с тех пор он не менялся. Достаточно узнать его на одном ПК, и злоумышленник получает доступ ко всем остальным. Хранится такой пароль обычно в таблице или в голове у администратора.

Задача состояла в том, чтобы у каждого компьютера был свой пароль, который сам меняется по расписанию и хранится там, где доступом можно управлять. Для этого выбран встроенный Windows LAPS: он входит в Windows 10/11 и Windows Server 2019 и новее после накопительного обновления от 11 апреля 2023 года, и отдельной установки не требует.

## Основные преимущества

**Уникальный пароль на каждом ПК:** взлом одного компьютера не открывает остальные. Атака, при которой один и тот же хэш пароля применяется на всех машинах, перестаёт работать.

**Автоматическая смена:** пароль меняется по сроку (в проекте 30 дней), и его не нужно помнить или записывать. Длина и сложность задаются политикой.

**Смена после использования:** если кто-то вошёл на ПК под локальным администратором, пароль считается известным. Через заданное время LAPS сам его меняет, а сеанс локального администратора завершает. Работа пользователя под доменной учётной записью не прерывается.

**Хранение в Active Directory с шифрованием:** пароль лежит в атрибутах компьютера в AD, а не в отдельной системе. Шифрование доступно при функциональном уровне домена 2016 и выше.

**Разграничение доступа:** читать пароли может только выделенная группа (в проекте это `LAPS-Readers`), остальным они не видны. Чтобы увидеть зашифрованный пароль, нужны два права: чтение атрибута и право расшифровки.

**Встроенное решение:** не нужны ни агент, ни лицензия, ни отдельный сервер. Всё настраивается групповой политикой и обычными средствами AD, а пароль виден на вкладке LAPS в оснастке «Active Directory — пользователи и компьютеры».

**Не мешает переименование:** если имя администратора не задано, LAPS находит встроенную учётную запись по SID (окончание -500). Переименование администратора на работу не влияет.

## Что понадобилось

| Что | Значение |
| --- | --- |
| Контроллер домена | Windows Server 2019 Standard |
| Решение | Встроенный Windows LAPS |
| Обновления | На контроллере и на всех ПК накопительное обновление не ниже 11.04.2023 |
| Клиенты | Windows 10/11 |
| Шифрование паролей | Функциональный уровень домена 2016+, проверка: `(Get-ADDomain).DomainMode` |
| Структура OU | Основная OU, внутри OU отделов и компьютеры; всё настраивается на основной OU и наследуется |

## Настройка по шагам

**Шаг 1. Расширение схемы AD.** Выполняется один раз на контроллере домена. Учётная запись должна входить в группу Schema Admins.

```powershell
Import-Module LAPS
Update-LapsADSchema -Verbose -Confirm:$false
```

**Шаг 2. Права на OU.** Тоже один раз, на основной OU. Разрешения наследуются во все вложенные OU. Сначала право компьютеров записывать свой пароль в AD, затем право группы техподдержки читать пароли (без него их видят только администраторы домена):

```powershell
Set-LapsADComputerSelfPermission -Identity "OU=Компьютеры,DC=contoso,DC=local"
Set-LapsADReadPasswordPermission -Identity "OU=Компьютеры,DC=contoso,DC=local" -AllowedPrincipals "CONTOSO\LAPS-Readers"
```

Путь к OU и имя домена нужно заменить на свои.

**Шаг 3. Групповая политика.** GPO привязывается к основной OU с компьютерами. Параметры находятся в разделе «Конфигурация компьютера → Политики → Административные шаблоны → Система → LAPS»:

| Параметр | Значение |
| --- | --- |
| Настройка каталога резервного копирования паролей | «Включено» и Active Directory. По умолчанию стоит «Отключено», и LAPS не работает |
| Параметры пароля | Заглавные, строчные, цифры и спецсимволы; длина 15–20; срок 30 дней |
| Имя управляемой учётной записи администратора | Не задано: встроенный администратор находится по SID |
| Включить шифрование паролей | Включено |
| Настройка авторизованных расшифровщиков паролей | `CONTOSO\LAPS-Readers`; если не задано, расшифровывать могут только администраторы домена |
| Действия после проверки подлинности | «Сбросить пароль и выйти из системы», период 8–24 часа |
| Не разрешать срок действия пароля, превышающий требуемый политикой | Включено |

Шаблоны политик уже есть на обновлённом Windows Server 2019. Если используется центральное хранилище, файлы `LAPS.admx` и `ru-RU\LAPS.adml` нужно скопировать в каталог `PolicyDefinitions` в SYSVOL.

**Шаг 4. Применение и проверка.** На тестовом компьютере в PowerShell от имени администратора:

```powershell
gpupdate /force
Invoke-LapsPolicyProcessing
```

Без `Invoke-LapsPolicyProcessing` пароль запишется при фоновой обработке, примерно раз в час. Остальные компьютеры подтянут политику сами.

## Как убедиться, что всё работает

Успешная работа видна в трёх местах:

- **Журнал на компьютере:** «Журналы приложений и служб → Microsoft → Windows → LAPS → Operational», событие 10018 (пароль записан в AD).
- **Оснастка ADUC на контроллере:** свойства компьютера, вкладка LAPS с именем учётной записи, паролем и сроком действия.
- **PowerShell на контроллере:** `Get-LapsADPassword -Identity ИМЯ_ПК -AsPlainText`.

Для повседневной работы пригодятся ещё две команды: `Reset-LapsPassword` на самом компьютере меняет пароль немедленно, а `Set-LapsADPasswordExpirationTime -Identity ИМЯ_ПК` на контроллере заставляет сменить его при следующей обработке.

## Траблшутинг

| Симптом | Причина | Решение |
| --- | --- | --- |
| Вкладка LAPS есть, но пустая | Компьютер ещё не отправил пароль | `Invoke-LapsPolicyProcessing` на ПК, затем журнал LAPS |
| `Invoke-LapsPolicyProcessing` не распознано | На ПК нет обновления с Windows LAPS | Поставить последнее накопительное обновление |
| «Отказано в доступе» в журнале | У компьютера нет права записи | Выполнить `Set-LapsADComputerSelfPermission` на нужную OU |
| GPO нет в `gpresult /r /scope computer` | ПК в другой OU или на OU отдела заблокировано наследование | Проверить `Get-GPInheritance`; при блокировке привязать GPO и к этой OU |
| Пароль виден только в зашифрованном виде | Учётная запись не входит в расшифровщики | Добавить в группу `LAPS-Readers` |

Если причину найти не удалось, команда `Get-LapsDiagnostics` на компьютере собирает архив с логами.

## Итог

**Что стало сложнее:** расширение схемы AD необратимо, поэтому его стоит делать осознанно и после проверки на тестовой среде. Чтобы записать новый пароль, компьютер должен видеть контроллер домена.

**Результат:** у каждого компьютера свой пароль локального администратора. Он сам меняется, хранится в AD в зашифрованном виде и виден только тем, кому это разрешено. Для этого не понадобились ни новые серверы, ни отдельные лицензии.

**Что изменилось в безопасности:** раньше один пароль открывал все компьютеры, и его утечка с любой машины ставила под угрозу весь домен. Теперь пароль, полученный с одного ПК, подходит только к нему и со временем устаревает. Компрометация одной машины не позволяет перейти на остальные, а пароли не хранятся ни в таблицах, ни в образах системы. Доступ к ним ограничен одной группой, и после каждого использования пароль меняется автоматически.
