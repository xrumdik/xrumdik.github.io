## О проекте

Корпоративный сайт редко меняется, но обслуживать его приходится постоянно: обновлять WordPress, плагины и темы, следить за версией PHP, копировать базу данных. Для сайта проектной организации с услугами, портфолио и блогом на трёх языках (русский, английский, казахский) это лишняя нагрузка и лишний риск.

Задача состояла в том, чтобы поставить сайт на другую основу: готовые страницы вместо сборки каждой из них при каждом запросе. Для этого выбран Astro. Он собирает сайт заранее в обычные HTML-файлы, и сервер отдаёт посетителю только их.

## Перенос без потерь

**Содержимое:** страницы, записи блога и работы из портфолио перенесены в файлы Markdown. Правка текста сводится к изменению файла и новой сборке, без админ-панели и базы данных.

**Адреса:** старые адреса WordPress не пропали. Постоянные переадресации (301) ведут с них на новые страницы, и посетители, пришедшие по внешним ссылкам или из поиска, не попадают на ошибку 404. После запуска Search Console показал, что старые адреса отрабатываются как переадресации.

**Поисковая оптимизация:** при каждой сборке автоматически создаётся карта сайта, для каждой страницы ставится канонический адрес, а языковые версии связываются между собой (hreflang).

**Три языка:** переводы хранятся отдельно от шаблонов, а при сборке автоматически видно, что ещё не переведено и что устарело после правки русского текста.

## Скорость и безопасность

**Скорость:** WordPress собирает каждую страницу при запросе: PHP обращается к базе данных, плагины подключают свои скрипты и стили. В Astro страницы собраны заранее, и посетитель получает готовый HTML-файл, без обращения к базе и без выполнения PHP-кода. JavaScript подключается только там, где он нужен, а файлы стилей и скриптов с хэшем в имени можно кэшировать в браузере надолго.

**Безопасность:** у статического сайта нет того, что обычно взламывают: входа в админ-панель, базы данных, плагинов и скриптов на сервере. Уязвимости плагинов и тем WordPress для такого сайта неактуальны: их там нет. Запросы к .php-файлам закрыты на уровне сервера.

**Проверка:** при каждом изменении проекта и каждый понедельник GitHub автоматически проверяет зависимости на известные уязвимости, ищет случайно попавшие в код пароли и ключи и применяет собственные правила проекта. Обнаруженные проблемы исправляются одним обновлением зависимостей, без вмешательства в работающий сайт.

## Сравнение с WordPress

WordPress строит страницу в момент запроса, Astro строит её заранее. Из этого вытекает остальное:

| Критерий | WordPress | Astro |
| --- | --- | --- |
| Как отдаётся страница | Собирается при каждом запросе (PHP и база данных) | Готовый HTML-файл |
| Что нужно на сервере | PHP, база данных, плагины | Любой веб-сервер, достаточно отдавать файлы |
| Обновления | Ядро, плагины, темы, PHP | Только инструменты сборки, проверяются автоматически |
| Главные риски | Уязвимости плагинов, взлом админ-панели | Минимальная поверхность атаки |
| Правка текстов | В админ-панели, без разработчика | В файлах Markdown с повторной сборкой |
| Формы, комментарии, личный кабинет | Плагинами | Внешними сервисами или отдельным кодом |

## Итог

**Что стало сложнее:** у сайта нет админ-панели, поэтому правки вносятся в файлы и требуют пересборки, а формы и комментарии подключаются отдельными сервисами. Для сайта, где содержимое меняется раз в несколько недель, это разумная цена. Для интернет-магазина или сайта с ежедневными публикациями от многих авторов выбор был бы другим.

**Результат:** перенос на Astro превращает сайт из «живой» системы, за которой нужно постоянно ухаживать, в набор готовых файлов: быстрый, безопасный и простой в обслуживании.
