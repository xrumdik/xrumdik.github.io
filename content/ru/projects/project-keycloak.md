## О проекте

Когда в компании несколько веб-приложений (облачное хранилище, почта, мониторинг), у каждого свои учётные записи и свои пароли. Пользователи путаются, а администратору при увольнении сотрудника приходится отключать доступ в каждом сервисе отдельно.

Задача состояла в том, чтобы вход везде был один и управлялся из одного места. Для этого выбран Keycloak: система единого входа с **открытым исходным кодом** (лицензия Apache 2.0). Она бесплатна, работает на собственных серверах и не привязывает компанию к чужому облаку.

## Как это работает

Приложение больше не проверяет пароль само. Вместо этого на его странице входа появляется кнопка «Войти через Keycloak». Дальше всё происходит так:

1. Пользователь нажимает кнопку, и приложение перенаправляет его на страницу входа Keycloak.
2. Keycloak проверяет логин, пароль и, если включено, второй фактор.
3. После успешной проверки Keycloak отправляет приложению подтверждение: «этот человек прошёл проверку, вот его имя и почта». Общаются они по стандартному протоколу OpenID Connect через API.
4. Приложение пускает пользователя. Пароля оно не видит и не хранит.

Если пользователь уже вошёл в одно приложение, в другое он попадёт без повторного ввода пароля.

## Пример подключения Nextcloud

1. В Keycloak создаётся отдельная область для компании (realm) и заводятся пользователи.
2. Для Nextcloud создаётся «клиент»: запись, которая говорит Keycloak, что этому приложению можно доверять. В ней указывается адрес Nextcloud, а Keycloak выдаёт секретный ключ.
3. В Nextcloud ставится приложение «OpenID Connect user backend». В нём достаточно указать адрес Keycloak, имя клиента и секретный ключ: остальные настройки Nextcloud получает сам.
4. На странице входа Nextcloud появляется кнопка Keycloak.

Пользователи, которые уже есть в Nextcloud, привязываются к входу через Keycloak по совпадению логина, их файлы и настройки сохраняются. Локальный вход администратора лучше оставить как запасной, пока всё не проверено.

## Пример подключения Mailcow

В Mailcow поддержка Keycloak встроена: в разделе System → Configuration → Access → Identity Provider выбирается Keycloak и указываются адрес и данные клиента, созданного заранее в Keycloak.

Особенность Mailcow в том, что почтовые ящики создаются автоматически: при первом входе через Keycloak для пользователя заводится ящик по заранее заданному шаблону. Домен должен уже существовать в Mailcow. Уже созданные ящики переключаются на вход через Keycloak вручную.

## Двухфакторная аутентификация

Главное удобство в том, что второй фактор включается один раз в Keycloak и сразу действует для всех подключённых приложений. Для каждого приложения отдельно настраивать его не нужно.

Пользователь при первом входе видит QR-код, сканирует его в приложении-аутентификаторе на телефоне (например, FreeOTP или Google Authenticator) и дальше вводит одноразовый код после пароля. Обязательность второго фактора включается в настройках Keycloak для всех или для отдельных групп.

## Что улучшилось

**Один вход:** один логин и один пароль для всех приложений, вход в следующее приложение без повторного ввода.

**Безопасность:** пароль знает только Keycloak, приложения его не видят. Второй фактор защищает все сервисы сразу.

**Управление доступом:** пользователей и права (по группам) ведут в одном месте. Уволенного сотрудника достаточно отключить один раз, и он теряет доступ везде.

**Меньше нагрузки на поддержку:** нет множества паролей, которые нужно сбрасывать и восстанавливать.

**Свободное ПО:** нет платных лицензий, данные остаются на собственных серверах, а в случае необходимости можно подключить другие приложения, поддерживающие OpenID Connect.

## Итог

**Что стало сложнее:** Keycloak становится точкой, от которой зависит вход во все приложения, поэтому ему нужны резервные копии и аккуратная эксплуатация.

**Результат:** пользователи входят во все сервисы компании через одну страницу, второй фактор включается один раз для всех, а доступом управляют из одного места на полностью открытом решении.
